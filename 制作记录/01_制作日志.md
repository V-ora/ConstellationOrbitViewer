## 2026-09-27 · 查看器立项与 v1

- 用户最初说"做个能看这些内容的程序"，我误做成通用文件查看器（`交付物查看器\`，后按用户要求删除，有备份）；

  + `web/index.html`（WebGL 3D 地球 + Canvas 2D 等经纬地图 + 时间轴 1×~900× + 筛选 + 详情面板）

  bat 双击不继承会话代理 → 探测链 = 环境变量 + 系统代理 + 常见端口扫描。

### start.bat 双击没反应（修复）
- 根因：① .bat 是 LF-only（Write 工具默认），cmd 解析错乱，rem 行里的词被执行；② 残留非 ASCII 注释变乱码命令。
- 修复：纯 ASCII + CRLF（`.encode('ascii')` 自检），中文提示挪到 Python 侧；server 开浏览器三级兜底 + 剪贴板 + 轮询端口再打开。
- 此教训进了用户级 MEMORY.md（.bat 两条死规矩）。

### 二轮：数据完整性 + exe 打包
- UI 微调（高轨红色/50° 绿色、点选置顶火箭遥号、悬停统一、"未正常升轨"阈值 1 年）+ 南极/北极渲染修复。
- ★核心发现：**CelesTrak FORMAT=tle 漏掉所有 6 位（Alpha-5）NORAD 号的星**（千帆漏 19、星网漏 9）；
  `CATNR=6位数&FORMAT=tle` 404 但 FORMAT=json 正常 → 改 OMM 主源 + `server.py: omm_to_tle()` 本地转 TLE
  （离心率截断不四舍五入、用 Decimal 避浮点坑；对 238 颗双格式星逐字符校验一致）。
  三星座编目数=显示数：257/186/3，no_tle=0；冷启动从 100s 降到 10~16s。
- 连锁 bug：local_meta 不按分组隔离（千帆元信息灌进星网）；负缓存把 502 当"没根数"封口 24h（改只认 404）。
- exe 打包：PyInstaller 6.22.3 onefile（spec_onefile.spec，9.6 MB）；FROZEN 资源走 sys._MEIPASS，
  缓存写 `%LOCALAPPDATA%\ConstellationOrbitViewer\cache`。归档 `交付物\06_星座轨道实时查看器\`。

### 三轮：南极绕极圈伪影
- 南极视角极点小圈 = 海岸线描边路径 -360/0/+360 三平移副本 closePath 画出水平弦线；

### 基线（优化前，`_refresh_20261015.log`）

一眼能看出钱花在哪：**两处占了 23.6 s（85%）** —— 截图和追平历史。

### 浪费点一：`_shot.mjs` 里的固定盲等（5.8 s → 1.4 s）

原脚本 `sleep(4000)` 后截图、再 `sleep(900)` 收尾。查了两处源码确认**根本不需要等**：
`gw_template.html` 里唯一的动效是 `table.lau tr{transition:background .12s}`（CSS hover 过渡），
`make_qf_html.py` / `make_gw_html.py` 里**没有任何 `requestAnimationFrame` / `setTimeout`** ——
大图是**同步一次性绘制**的 canvas，画完就是画完了。

改成三层**条件等待**（每层超时只 `console.log('WARN: …')`，不强退）：

1. `document.readyState === 'complete' && !!document.getElementById('cv')`，上限 15 s；
2. **canvas 像素稳定**：每 150 ms 采样一次非空像素数，**连续 5 次不变**才放行，上限 12 s；
3. 布局稳定：`document.documentElement.scrollHeight` **连续两次相同**，再留 120 ms 合成时间。

★ **这里差点栽一个坑**：第一版判据写成「非空像素 > 0」，实测跑出 **`非空像素=221000`**（正常 **1161615**）——
画布是**先画背景/网格、再逐层画曲线**，221000 时已经 > 0 但**只有半张图**。
改成「连续 N 次采样不变」才对。讽刺的是那次的 PNG 竟然和正确版**逐字节相同**（`3ee181d1…`），
所以问题没暴露在产物上 —— **但判据必须收紧，否则迟早真截到半张**。
（「不报异常的错」又一次应验。）

### 浪费点二：`local_backfill.py` 的「代理优先」（11.9 s → 3.4 s，最差 82 s → 3.3 s）

`_OPENERS` 原来固定 **代理 → 直连**。本机代理时好时坏，`--dry` 实测最差跑出 **82 s**
（实测此时代理 2.79 s / 直连 2.43 s **都通**，纯粹是失败重试在烧时间）。
改成**直连优先**，并用 `_GOOD[0]` 记住上次成功的 opener 下标，后续请求先试它。

再把**高轨 3 颗与两个组接口并发**发出（`ThreadPoolExecutor(max_workers=5)`，A 段 / B 段分开计时）。

★ 一个被顺带否掉的「优化」：想把高轨三颗合成一次请求 ——
`gp.php?CATNR=59069,60327,61503` 直接回 **`Invalid query: "..." (CATNR=… is not an integer)`**
（`CATNR` 只收整数、不支持逗号）。所以**只能并发、不能合并**。

### 顺带修掉一个真 bug：exe 侧的 extras 被清空了

10-15 那轮把 `write_extras()` 改成「剔掉与库逐点相同的条目」，理由是 extras 别滚成整库副本 ——
**对源码版是对的，对 exe 是错的**，因为**两个入口的「基线」不是同一份**：

| 入口 | 基线 | 与磁盘库相同的点 | 结论 |
| --- | --- | --- | --- |
| 源码 server | 磁盘 `data\sat_hist.json`（每轮刚更新） | 才是重复，该剔 | 去冗余正确 |
| **exe** | **打包时打进包的** `data\sat_hist.json`（越来越旧） | 对 exe 是**它还没有的新点** | **去冗余 = 把增量清空** |

症状：`%LOCALAPPDATA%\…\cache\sat_hist_extra.json` 从 **480 颗 / 209 KB** 被清成 **0 颗**，
`_verify_exe_payload.py` 报 **34/6 FAIL**（`FAIL 内嵌 sat_hist.json 与磁盘不一致`）——
**exe 里的逐日历史静默停在打包日**。

修法：`write_extras()` **按入口分策略** ——
exe 侧（路径以 `%LOCALAPPDATA%` 开头）**从库直接重建「最近 30 天」的点**，不做去冗余；
源码侧维持去冗余。

★ 为什么 exe 侧**必须从库重建、不能只靠本轮 `appended`**：同一天重复跑 refresh 时追加 0 颗，
`appended` 是空的，靠它就漏了。（480 颗 × 30 天 ≈ 209 KB，可接受。）
★ 为什么重建时**保留重复点无害**：`_hist_append_pts` 本身会完全去重
（同 `t` 同高度不追加、同 `t` 差 >50 km 判脏点拒收）。

同步改了 `_verify_exe_payload.py` 的判定语义：
包内大图**只要存在且非空**即通过（有 `web_live\raise\` 覆盖层时允许包内旧）；
包内 `sat_hist.json` 落后时**必须**能在 `%LOCALAPPDATA%` 找到 **>200 B** 的 extras 才算通过。

### 三、局域网：`server.py --lan`（手机能连的前提）

原来默认只听 `127.0.0.1`，且 `init_allowed_hosts` 在绑 `0.0.0.0` 时**白名单仍是「仅回环」**
⇒ 手机拿 `http://192.168.x.x:8770/` 打开会被 Host 校验 **403**，症状是
「电脑上一切正常、手机转圈后白屏」，极难往安全校验上想。

改法：绑 `0.0.0.0` 时置 `_LAN_MODE`，额外放行**私有网段 IP 字面量**
（10/8、172.16/12、192.168/16、169.254/16 + IPv6 链路本地/ULA）。**域名一律仍拒绝** ——
DNS 重绑定的前提是攻击者只能用域名，他没法让自己的域名同时是 `192.168.1.7` 这个 Host 字符串。
`origin_ok` 同步放开。新增 `/api/net` 回地址给页面用。

`desktop.py` 默认绑 `0.0.0.0`（`COV_LAN=0` 可关）；`start.bat` 加 `--lan`；
`server.py` 启动时把局域网地址直接印在窗口里（不用去 `ipconfig` 里找 IPv4）。

### 踩坑（本轮四个，都写进 02 清单）

1. **`Array.prototype.slice.call(map.values())` 返回空数组**。`Map.values()` 是迭代器、
   没有 `length`，slice 当成长度 0 ⇒ `p[0].x` 抛 TypeError，捏合分支整段没跑完。
   症状极具误导性：抽屉、遮罩全好，只有 pinch 无效。改 `Array.from(live.values())`。

2. **「先取消、再被设上」**：想在第二根手指落下时补发 `pointercancel` 把主脚本的 `drag`
   置空，结果地球照样被转 16.8°。两次误判：先以为是 capture/bubble 顺序（改成冒泡，仍转），
   真正原因是**主脚本的画布监听器在 `DOMContentLoaded` 的 `boot()` 里才注册，比 mobile.js 更晚**，
   所以当场发 cancel 之后主脚本的 pointerdown 才跑、又把 drag 设上。
   最终解法：**放微任务里发**（`queueMicrotask`）——本轮 pointerdown 的所有监听器跑完才取消，
   与注册顺序彻底无关。教训：别靠「注册先后」这种隐式约定，改用「本轮结束之后再做」。

3. **断点 820 卡在手机横屏里**：iPhone 14 横屏是 844×390，`≤820` 不命中 ⇒ 掉回三栏，
   舞台被挤成 **318×275**。改到 900；同时给 `(max-height:460px)` 横屏矮窗加一条
   「视图切换收回第一行」，头栏 82 → **43px**。

4. **缩窄侧栏把卫星列表顶到页脚底下**：`≤1100` 本想 300/320 → 252/274 给地球腾地方，
   结果侧栏一窄「星座数据源」卡片换行变高，列表第一行 y=832~858、**中心点 845 落在页脚上**，
   `_selfcheck.mjs` 的「7a 已选中且按钮出现」变红（真实鼠标点击按坐标命中，点到了 FOOTER）。
   定位手法：`document.elementFromPoint(中心点)` 打出命中链 → 第一层就是 `FOOTER`。
   **决策：去掉缩窄**，省下的 96px 不值得。

5. 附带：自检脚本里 `waitFor(..., 25000)` 的 `25000` 写进了模板字符串，
   `maxMs` 变成 `undefined` ⇒ `Date.now()-t < undefined` 恒 false，等待循环一次都不跑，
   三个「页面数据加载完成」假红。教训：**多行模板字符串的收尾反引号位置要盯一眼**。
