## A. 真问题

### A1　2D 覆盖圆在非赤道处几何是错的（3D 是对的 → 两视图互相矛盾）

**证据（代码）**：`web/index.html:1435`

```js
g.ellipse(p[0], p[1], gr / 360 * L.mw, gr / 180 * L.mh, 0, 0, Math.PI * 2);
```

横竖半径都等于 β（地面角半径），即把 β 当成**纬度差**画正圆。2D 是等距圆柱投影，只有星下点在**赤道上**时这个做法才恰好正确。

**证据（数值，R = 6378.137，千帆 1068.5 km、最低仰角 10° → β = 22.488°）**

| 星下点纬度 | 同纬真实经度半跨 | 2D 画出 | 真实纬度下/上界 | 备注 |
|---|---|---|---|---|
| 0° | 22.5° | 22.5° | −22.5 / 22.5° | 唯一画对的位置 |
| 20° | 24.0° | 22.5° | −2.5 / 42.5° | |
| 45° | 32.0° | 22.5° | 22.5 / 67.5° | 少画 30% |
| 60° | 45.9° | 22.5° | 37.5 / 82.5° | 少画 51% |
| 70° | 69.5° | 22.5° | 47.5 / 90.0° | 2D 椭圆上界越过极点（无意义） |
| 80° | 180.0° | 22.5° | 57.5 / 90.0° | **真实是绕极极冠（整圈 360° 经度都在圆内）** |
| 89° | 180.0° | 22.5° | 66.5 / 90.0° | 同上 |

- 圆是否含极的判据：星下点纬度 > **67.51°**（= 90 − β，按 10° 仰角）。
- **影响面不小**：千帆是 89° 极轨（工作轨道 1068.5 km），大量卫星长期处于高纬，2D 圈严重失真。
- **3D 视图是对的**：`web/index.html:1258-1262` 用 `β = acos(cos e / rr) − e` 得真角半径，再在球面上取切平面基画闭合圈——那里 β 是真中心角，所以 3D 无需改动。

**选项**

- **A**：在 2D 里改用 3D 那套球面基，把圆周采样成经纬度折线再投影（自动处理极冠；极区跨 ±180° 经线要断笔，`web/index.html:1418` 已有现成断笔写法可套）。代价：每颗选中星每帧多约 30 次三角函数。
- **B**：保持现状，但在图例与 `说明.md` 里明确标注「2D 覆盖圆是低纬近似，高纬请以 3D 为准」。
- **C**：不动。

> **✅ 后续（2026-10-07 深夜）**：采用**比 A 更直接的做法** —— 不采样 3D 的球面基折线，而是新增
> `capColumns(lat0, β, N)` **逐列闭式解**出纬度上下界（`A=sinφ0, B=cosφ0cosΔlon, R=hypot(A,B)`），
> 再连成闭合多边形；含极点的绕极横带按 `1×/3×` 沿经度复制后裁到地图矩形（不用断笔，接缝也不缺块）。
> 缓存按 `lat0` 量化到 0.5°，`Map` 超 900 条整体清空。实测在 60 fps 下无压力（比逐帧 30 次三角函数的 A 方案更省）。
> ★ 另：**修这个新算法时又发现它自己的一个 bug** —— 两个解在 φ0 < 0 时相差 360°，
> **必须先各自归一化到 ±180° 再筛 [−90, 90]**，否则南半球高纬极冠会少画一半（是给南半球补断言才抓出来的）。
