# Space-Track 账号暂停与整改（2026-10-26 起）

## 一、事件

2026-10-26 03:20（邮件时间）Space-Track 以「API 使用政策违规」暂停账号 `2608872439@qq.com`。
原文指出的具体违规：

> downloading data from the SATCAT API more than once per day.
> Satellite Catalog data is only updated once per day by the 18th Space Defense Squadron after 1700 (UTC).

并要求：「Please disable your automatic scripts until you can refactor them」，
回信说明整改方案后才在下一个工作日恢复。

## 二、根因（自查确认）

| 项 | 事实 |
|---|---|
| 违规接口 | `class/satcat` |
| 违规工程 | **火箭末级追踪查看器**（`server.py` 的 `launch_raw()`、`build_snapshot.py`） |
| 单次刷新 | 对**每一发**火箭各查一次 `satcat/INTLDES/~~<COSPAR>` —— 58 发 = 58 次 |
| 触发频率 | 自动刷新 `REFRESH_TTL = 6h`（定时器 `AUTO_TICK=600` 每 10 分钟检查一次） |
| 折算 | ≈ **232 次 SATCAT/天**，政策上限 1 次/天 |
| 次要违规 | 星座轨道 SpaceTrack 版 `server.py`：按组名 / 按批次各查一次 satcat |
| 无关 | 黎明星座、星链只用 `class/gp`，不碰 SATCAT；网页版与 GitHub Actions 从不访问 ST |

## 三、整改（全部已落地并验证）

| 层 | 措施 | 位置 |
|---|---|---|
| 急停 | `ST_PAUSED` 标记 / `COV_ST_PAUSED=1` → 传输层在**登录之前**就拒绝 | 四个 `st_source.py` / `st_data.py` |
| 政策 | SATCAT（非 `/file/`）每 UTC 日最多 1 次，超限抛错；发起前记账 | 同上 |
| 增量 | 首次全量，之后每天只取 `class/satcat/file/>NN`，按 NORAD 合并本地库 | 火箭 `satcat_store()`、星座 `st_satcat_all()` |
| 共用 | SATCAT 库、日限标记、出站台账统一放 `%LOCALAPPDATA%\SpaceTrack\` | 同上 |
| 限流 | **跨进程**共享账本：整机 ≥2.1 秒/次、≤200 次/小时 | `_shared_slot()` |
| 台账 | 每次出站记 UTC 时间 + URL 到 `st_calls.log` | 同上 |
| 清理 | `_probe_st2.py`（裸 urllib、无间隔）加 `--i-know` 运行闸 | 星座根目录 |

标记文件的落点（任一存在即封）：工程目录、程序缓存目录（`%LOCALAPPDATA%\<App>\`）、共享目录。

## 四、验证记录

- 共享限流：3 个独立进程各要 3 个名额 → 最小间隔 **2.10 秒**、总跨度 16.9 秒（理论 16.8）。
- 小时预算：铺满 200 次后再申请 → 被挡，需等 1610 秒。
- 跨程序 SATCAT 日限：A 程序写入「今天已用 1 次」→ B 程序查询被拒。
- 增量逻辑（桩数据离线跑真函数）：全量 1 次 → 同日 0 请求 → 次日 1 次 `file/>9250` → 合并 4 条、`last_file` 推进到 9251。
- exe 行为：火箭/星座ST版/黎明/星链 四个新 exe 强制刷新时，日志全部是
  「Space-Track 出站已暂停（存在 …ST_PAUSED）」，**零流量**，界面数据仍从缓存正常显示。

## 六、遗留

1. `FILE` 字段的真实返回未验证（账号仍停）：若返回里没有 `FILE`，表现为每天重复拉同一份增量，
   仍是每天 1 次、不违规，只是略浪费流量。
2. 跨进程账本只覆盖**同一台机器**；两台电脑同时跑仍会叠加（各 200/h）。如需解决，要把账本放到共享目录。
3. 账号恢复后：删掉三处的 `ST_PAUSED`，再按回信里承诺的画像跑一次，检查 `st_calls.log`。
