# 关键经验与踩坑清单（星座轨道实时查看器）

> 从四天制作日志中提炼，动手改代码前先读一遍。详细出处见 `01_制作日志.md` 对应轮次。

## 一、CelesTrak 数据源（最贵重的教训）

1. **一天只做一轮完整抓取**。403 档约 1 小时、丢包档约 78 分钟自动解封，但 40 分钟 100+ 请求会把新 IP 也打封。
   验证一律用缓存/离线手段。
2. **FORMAT=tle 漏全部 6 位（Alpha-5）NORAD 号**（千帆漏 19、星网漏 9）；`CATNR=6位数&FORMAT=tle` 404 但
   `FORMAT=json` 正常 → OMM 主源 + 本地 `omm_to_tle()` 转换（离心率**截断**不四舍五入、Decimal 避浮点坑）。
3. `graph-orbit-data.php?CATNR=` 的 plotData 列名叫 SMA，实为**平均轨道高度 = 半长轴 − 6378.137 km**。
4. CelesTrak 无历史根数 API（EPOCH= 参数被无视）；免费历史 TLE 源（SatNOGS/Wayback）均不可行。
5. 编目检索用 `satcat/records.php?INTDES=前缀&FORMAT=json`（search.php 是表单 POST，脚本被 WAF 吐空）；
   satcat.txt 有滞后且列位：intdes 0-12、NORAD 13-18。
6. 限流独立：records.php 与 gp.php 互不牵连；403 按 IP 封，代理/直连同封。
7. 爬升状态判定用**中位数窗口**（近 10 天 vs 20–38 天前），不用单点差值——历史序列有单点跳变会误判降轨。
8. 中国火箭**遥号 ≠ 发射次序**，不能反推；同日两次发射按 COSPAR 前缀拆批。

## 二、前端 / 渲染

9. **改完 UI 必须 CDP 真实输入自检**：合成 `dispatchEvent(new MouseEvent("click"))` 不走 pointer capture 流程，
   测不出 setPointerCapture 抢事件这类 bug；必须 `Input.dispatchMouseEvent` + elementFromPoint + 捕获探针。
10. **CDP 测试必须先设视口**（Emulation.setDeviceMetricsOverride 1600×900）；无头默认视口 #stage 塌缩成 0 宽全盘假；
    视口太矮（如 571）会把 #list 挤成 0 高产生假阴性。
11. `.overlay` 类默认 `pointer-events:none`——浮动层内部可交互元素必须显式 `pointer-events:auto`，
    否则整排按钮"死了"且难以察觉（潜伏到用户偶然使用才暴露）。
12. stage 拖拽的 `setPointerCapture` 会把后续 mouseup/click 全部重定向到 stage——面板（stage 子元素）内按下要提前 return。
13. **Date.UTC 月份 0 起算**：`"2024-01-01".split("-")` 直喂 Date.UTC 会把 1 月当 2 月，时间轴整体 +1 月。
    数据层对 ≠ 渲染层对，轴生成代码要单独验。
14. iframe 内部页面有状态时，切换参数**一律用 query 不要用 hash**（hash 变化不触发导航）。
15. canvas 曲线绘制要 clip 裁剪（陡直爬升线溢出到坐标轴区）；发射刻度/气泡在 restore() 之后画才不被曲线盖住。
16. 密集时间轴标注不能用文字——组号小气泡 + 多行贪心避让。
17. 被 iframe 进 App 的大图页统一加嵌入态检测：`if (window.parent!==window) body.classList.add('emb')`
    + `body.emb header{padding-top:…}` 躲右上角按钮条。
18. echarts.min.js 内部字符串含 `</body>`，往 HTML 注入内容要 rsplit 取最后一个匹配。
19. 向 iframe 内元素派发父页面鼠标事件，坐标必须加 iframe 的 x/y 偏移。
20. Python 生成 HTML 时，**str.format 占位符不一定真的在模板里**——星网大图的 `__TABLE__` 是死代码
    （表格由 JS 渲染），改它不生效。两套渲染并存时先确认渲染路径。
21. WebGL 与 2D 不能同 canvas 混用（两块叠放）；等经纬投影极地环要沿图边（±90°）闭合，
    描边的三平移副本环绝不 closePath（否则极点绕圈伪影）；JS 月份、TLE padEnd(69) 同理都是"数据对渲染错"家族。

## 三、服务端 / 架构

22. **降级路径必须和主路径一样快**：联网失败 mode=none + 5 分钟冷却秒回缓存，绝不复活死代理、绝不每次重撞超时。
23. stale-while-revalidate：有缓存无条件先回缓存（<0.02s），后台刷新，前端静默轮询换新——打开速度根治。
24. 元信息持久化 `cache/<group>_metamap.json`（重启免联网）；种子脚本跑 fetch_group_meta 前必须先 load_launches()，
    否则残缺 metamap 污染缓存。
25. 负缓存只认 404（502/网络抖动不能封口 24h）；INTDES 检索首败即退避（否则几十批超时拖住首屏）。
26. exe 版本守护：server BOOT_ID + 页面 10s 轮询 → 程序更新后旧标签页自动弹刷新提示条
    （用户"点了没反应"的第一嫌疑是他在旧标签页）。

## 四、Windows / 打包 / 交付流程

27. `.bat` 必须 **CRLF + 纯 ASCII**（Write 工具默认 LF 会崩，rem 行里的词被执行）；中文提示放 Python 侧。
28. exe 更新全流程：打包 → taskkill 全部旧实例（onefile 双进程）→ cp → **MD5 两侧核对** → run_in_background 启动
    → curl /api/ping 验证 boot。⚠️ 命令内 `... & sleep` 起 exe 会被 shell 带走，必须 run_in_background；
    后台起服务禁止接管道（SIGPIPE 掐死服务 / BrokenPipeError 秒崩）。
29. 打包时 web/ 打进 exe——改了 web/ 或大图必须重打包；PYTHONPATH 指向 venv site-packages
    `C:\Users\t2007\.workbuddy\binaries\python\envs\default\Lib\site-packages`。
30. 判断进程死活用 `netstat -ano | grep <端口> | grep LISTEN`（中文镜像名 tasklist grep 不到，编码问题）；
    exe 后台进程被工具回收 ≠ 崩溃，以"重启复现"为准。
31. 本机删文件不进回收站（send2trash/COM 都被拦）：先 zip 备份再 os.remove。
32. 大范围文件搬移：先备份 zip → move → MD5 对账；动手前后都重新 os.walk 核对真实状态
    （可能存在并发会话进程，不要信上一步的快照）。
33. curl 测本机服务要 `--noproxy '*'`（会话代理把 127.0.0.1 也隧道转发，进程一死报 502 干扰判断）。
34. 无头 Edge 截图验证 HTML 图表是交付前的最后一步：`--headless=new --enable-unsafe-swiftshader
    --virtual-time-budget=25000 --screenshot`，配合 `--enable-logging=stderr` 抓 JS 报错。

## 六、2026-10-07 新增踩坑（覆盖圆 / 过境预报轮）

40. **PyInstaller 覆盖 dist 里同名 exe 会被本机安全策略拦下**：报 `OSError: SHFileOperationW 失败: 0x2`，
    之后**旧 exe 已被删、新 exe 没生成**，日志看起来像"打包失败"，其实产物目录空了。
    → 打包前先把要覆盖的 exe **`mv` 走**（别用删除），再让 PyInstaller 写新文件。
41. **四个 exe 各用独立 `--workpath`**（`wp_main` / `wp_main_d` / `wp_nopass` / `wp_nopass_d`）：
    两套变体共用 workpath 时，PyInstaller 的 Analysis 缓存有互相污染的风险（把含过境预报的页面打进变体里）。
    `_verify_exe_payload.py` 拆包核对能兜住这类错误，但**别依赖兜底**。
42. **`<b>` 落在 `display:flex` 的容器里会变成独立 flex 项**：图例 `.legend .li{display:flex;gap:7px}`，
    中间插一个 `<b>` 会让整句被切成 3 块、换行错位（把"最低/仰角"竖着排）。
    → 用一个 `<span>` 把整句包成一个 flex 项再在内部加粗。
    ★ **这个缺陷自检脚本查不出来，是截图肉眼发现的**——UI 改动做完**必须截图看一眼**，别只看 PASS。
43. **`_chk_*.mjs` 各自占用固定 CDP 端口**（`_selfcheck` 9333 / `_chk_qf` 9334 / `_chk_pass` 9335 /
    `_chk_gw` **9336** / `_chk_bp` **9336** / `_chk_cover` 9337 / `_chk_bp_emb` 9338）。
    **连续跑必须间隔几秒**，否则前一个 headless Edge 没退，后一个直接 `FATAL: CDP target 未就绪`——
    这是**环境问题不是被测程序的问题**，隔几秒重跑即可。
44. **偶发单次 FAIL 先复跑再定论**：例 `_chk_pass.mjs` 的「计算期间重复触发不重入」，
    如果那次计算在 250 ms 内已经跑完，就没"in-flight"可重入，`same:false` 是**时序抖动**，复跑即过。
45. **"改页面后忘了同步变体页"是高频事故**：`web/index.html` 与 `_features/index_original.html`
    必须同步改（凡是不依赖过境预报的改动）。`_make_nopass.py` 现在带**页面指纹守卫**：
    指纹不符就停下并给出处置指引，`NO_PASS_ACCEPT=1` 重跑一次可自动回填新指纹。
46. **验证要打到"用户手里的二进制"**：所有 `_chk_*.mjs` 都支持传 URL，所以可以**先双击 exe、
    再对着它跑专项脚本**。2026-10-07 就是这么确认覆盖圆改动真的进了发布 exe（`_chk_cover.mjs` 38/0）。
47. **"覆盖圆"这类几何量，最靠谱的验证是读渲染器真正画出去的东西**：
    2D 里**暂停时间轴**后用「关/开」两帧做**像素差分**（逐像素 `|ΔR|+|ΔG|+|ΔB| > 20`），
    从 bbox 反推面积 / 东西跨度 / 纬度上界（`lat = 90 − (y−oy)/mh*180`）；
    3D 里同样先暂停、再用 `gl.readPixels` 做冻结帧差分。
    比"读代码里的公式"强得多——公式对、但画错的情况是存在的。
    再用 `_probe_cap_edge.mjs` **逐列**提边界、与**不复用页面代码**的闭式解比，能做到 1 px 级复核。
48. **仰角口径要跟物理事实对齐**：覆盖圆的 `β = acos(Re/(Re+h)·cos e) − e`，
    `e = 0` 就是旧口径的几何地平线。同一个控件值**必须与过境预报共用**，
    否则两处都叫"最低仰角"却能给出互相矛盾的数字；改值时要顺手**把已算出的过境结果作废**。
    ★ 展示这类几何量时**一定要写清它不是什么**（不是通信覆盖/服务区），否则容易被当成链路口径用。
49. ★★ **等经纬度地图上不能把球面角半径当"圆的半径"画**：覆盖区在球面上是**球冠**，
    投到等距圆柱世界地图上**根本不是椭圆**。把 β 同时当经差和纬差，只在**赤道**成立；
    β=22.5° 时东西半跨 45°→32.7°、60°→49.9°、80°→**180°**（球冠含极点 ⇒ 绕极横带）。
    **症状是"高纬少画一大半"**，而低轨极轨星座（千帆 89°）常年飘在高纬 ⇒ 影响面很大。
    → 正解：逐列解 `A=sinφ0, B=cosφ0cosΔlon, R=hypot(A,B)`，`R<cosβ` 判整条经线在圆外；
    含极点的绕极横带要**沿经度 1×/3× 复制**再裁到地图矩形（否则接缝缺一块）。
    ★★ **两个解必须先各自归一化到 ±180° 再筛 [−90, 90]**：φ0<0 时 `atan2` 落到 ±180° 附近、
    两个解相差 360°，不归一化会让 `hi<lo` 触发护栏、**一整片连续经线被丢掉**
    （症状：南半球极冠只画一半 + 地图接缝多一条竖直边）。
50. ★★ **查几何必须跨纬度 + 跨半球；只测一个纬度/半球等于没测**：
    上面那个归一化 bug 在赤道和北半球完全看不出来。而且别用"碰到的第一颗高纬星"
    （`S.sats.find(|lat|>75)` 会随模拟时刻在南北极之间漂移，**只有南半球走归一化分支**）——
    要**显式**跑 `x.lat>75` 和 `x.lat<-75` 两遍。做几何改动的验收一律加：赤道 / 中纬 / 高纬 / 两极。
51. **写基于像素测量的自检时，我自己踩的 4 个坑（全是测试错、不是程序错）**：
    ① β 要用**该星自己的高度**算（拿基准高度 1068.5 km 的 β 去比 1100 km 的星，平白差 0.5°）；
    ② `oy/mh` 必须在**测量那一刻重读**版面（选中不同的星会改右侧面板高度 → 2D 画布尺寸变）；
    ③ 测量函数开头**强制暂停时间轴**（否则两帧之间卫星自己挪，差分被污染）；
    ④ 断言调 `capColumns` 时用 `N=3600`（`N=360` 的 1° 经度格会把东西半跨量化截断成 22.0 vs 真值 22.5）。
52. **开关类 UI 的语义要两视图一致，并且要专门测"关掉真的不画"**：旧 2D 判据是
    `isSel || (S.coverOn && !S.selected)`——**选中星时无视开关照画**，按钮形同虚设，而 3D 是守开关的。
    测法：`S.coverOn=false` 且选着一颗星，量 2D「关/开」差分 = 必须为 **0 像素**。
    ★ 判断"这是不是本轮引入的"用 `PyInstaller.archive.readers.CArchiveReader` 从**旧 exe** 里抽内嵌页面比对
    （**必须用 venv python**，普通托管解释器 import 不到 PyInstaller）——本次证明该谓词是**历史遗留**。

## 附：Space-Track 数据源专项（2026-10-09 移植自星链查看器时新踩/复核过的）

1. **两家字段名同构、值不同构**：CelesTrak 的 OMM JSON 就是 Space-Track GP 的镜像，键名一致
   （`NORAD_CAT_ID`/`OBJECT_ID`/`MEAN_MOTION`…），**所以 `omm_to_tle` 能直接吃 ST 的行**；
   但**值的写法会差**：ST 的 `MEAN_MOTION_DDOT=0` 官方 TLE 写 `" 00000-0"`（拼装给 `+0`，校验位差 1）、
   偏心率 JSON 只给 8 位小数而官方 TLE 用全精度（截断/四舍五入都可能差 1）⇒ **ST 模式直接用 `TLE_LINE1/2`**。
2. **`gp` 的名字是原始设计名，`satcat`/CT 的名字是整理名**：高轨三星 ST 叫 `HG-01`（CT 叫 `HULIANWAN GAOGUI-01`）、
   千帆 `2026-211` 批 ST 就叫 `OBJECT A`。**任何关联都不要按名字，按 NORAD**；查不到就按 COSPAR/NORAD 直查。
3. **`OBJECT_TYPE` 有两套值域**：`gp`/`satcat` 用全称 `PAYLOAD / ROCKET BODY / DEBRIS / UNKNOWN`，
   CT 用缩写 `PAY / R/B / DEB / UNK`；**而且未命名载荷是 `UNKNOWN` 不是 `PAYLOAD`**
   （只留 PAYLOAD 会把 `OBJECT A~K` 全滤掉，只留 PAY 又会放进火箭残骸 ⇒ 收 `PAY`+`UNK`）。
4. **`OBJECT_ID` 前缀检索会带出同批火箭残骸**：`~~2026-211` 里混着 `GRAVITY-1 R/B`，
   CT 的编目组没有它 —— 不滤就比 CT 多 1 颗。
5. **限额是硬的 30 次/分钟、300 次/小时，登录也占配额**：必须「会话复用 + 全局限流 + 429 退避」三件套，
   否则缺星补抓一批就打满。（会话实测可活数小时，代码取 20 分钟保守值。）
6. **CT 的编目组是人工维护的**：`GROUP=qianfan` 的成员当天实测在 256↔257 之间来回（新编目星要等挂组），
   **ST 侧可能先有**。`_audit_data` 的逐 NORAD 对齐因此把「服务端多、CT 少」降级为 WARN（缺星才 FAIL）。
7. **未编目号的行为不同**：CT 的 `CATNR` 未编目 → HTTP 404；ST 的同查询 → **空数组**（不是 404）。
   负缓存（`*_noTLE.json`）两条路径都要认。
8. **缓存目录必须按来源分开**：两版共用 `cache/` 会让「刚刷新过」的时间戳互相踩；
   ST 版用 `cache_st/`。**调试时注意**：`*_metamap.json` 有 2 小时 TTL，早期用旧口径写的盘缓存
   会被服务端直接复用（「显示数 257、编目数 248」的假象就是这么来的）→ 改口径后先删盘缓存再验。
9. **凭据文件不能打进 exe**（`spacetrack.txt` 与 exe 同目录或放主目录）；`COV_RUNTIME_HOOK` 是
   给变体 exe 注入环境变量的正解（环境变量在打包时设了不会进包）。

## 附：悬停提示框（tooltip）自适应定位（2026-10-10 用户截图反馈）

1. **不能「估一个最大宽度」再钳制**：`Math.min(clientX + 14, innerWidth - 200)` 只在
   「提示框恒比 200 px 窄」时才成立；组次叠加图提示框最多 14 行、实测 255~270 px，
   右侧照样伸出去被裁掉（用户看到数值只剩「· 10」）。**正解：`display:block` 之后用
   `offsetWidth/offsetHeight` 实测尺寸**再决定往哪边摆。
2. **「翻转」≠「夹边」**：只做 `Math.max(8, …)` 的夹取会让框贴着边缘、仍盖住鼠标或被裁一半。
   要「右侧装不下就整框翻到鼠标左侧、下方装不下就翻到上方」，只有框比视口还大时才退化为夹边。
3. **四个方向都得兜底**：只写「右越界则左移、下越界则上移」不够——鼠标在视口外时
   （画布被滚出视口、`e.clientY` 为负数）`cy + dy` 本身就出界，必须补
   `if (left < m) left = m;` / `if (top < m) top = m;`。（这条是自检 T5 抓出来的真实缺陷。）
4. **同一份代码散在 5 处，改一处必顺改其余**：`web/raise/batch.html`、`web/raise/sat.html`、
   `raise_batch_panel.html`、`make_qf_html.py`（内联模板，注意是 `r"""…"""` 里的 JS）、

## 附：刷新管线提速 + 两个「静默错」（2026-10-19，用户「刷新太慢」）

1. **★ 上一节第 2 条要加一个前提，否则会修出新 bug**：`sat_hist_extra.json` 确实不该滚成整库，
   但 **「剔掉与库逐点相同的条目」只对源码版成立**。因为两个入口的「基线」不是同一份：
   源码版的基线 = **磁盘** `data/sat_hist.json`（每轮刚更新）；**exe 的基线 = 打包时打进包的那份**
   （越来越旧）⇒ 与磁盘库相同的点，**对 exe 恰恰是它还没有的新点**。按磁盘去冗余 = 把 exe 的增量清空，
   exe 里的逐日历史**静默停在打包日**（实测 extras 480 颗/209 KB → 0 颗）。
   ⇒ `write_extras()` 现按入口分策略：**exe 侧从库重建「最近 30 天」，不做去冗余**。
   **判断「两个入口共用一份缓存」时，先问「它们各自的基线是什么」，不要只看最终文件长什么样。**
2. **exe 侧重建不能只靠本轮 `appended`**：同一天重复跑 refresh 时追加 0 颗，`appended` 是空的，
   靠它就漏了 ⇒ 必须**遍历 `base_sats` 取最近 30 天**重建。保留重复点无害（`_hist_append_pts` 自身会去重）。
3. **★ 固定 `sleep()` 盲等是纯浪费，但要换对判据**：大图是**同步一次性绘制**的 canvas
   （模板里只有 CSS hover 过渡、生成器里没有 `rAF`/`setTimeout`），所以不必等；
   但「canvas 画完」**不能只判非空像素 > 0** —— 画布先画背景/网格就已经 > 0（实测 **221000**，
   画完是 **1161615**），必须判**连续 N 次采样像素数不变**。超时一律只 `WARN` 不强退。
4. **并行截图必须错开 CDP 端口**：`_shot.mjs` 端口改成读 `SHOT_DBG`；两个进程同端口时，
   第二个会连到**第一个的浏览器实例**上，**截图内容会串**。
5. **代理顺序反了会让每次请求白等超时**：`local_backfill.py` 原来固定「代理 → 直连」，
   本机代理时好时坏，实测最差 **82 s**（正常只要 3~4 s）。改成**直连优先 + 记住上次成功的 opener**，
   并把高轨与两个组接口**并发**。★ 顺带否掉一个「优化」：CelesTrak 的 `CATNR` **不支持逗号批量**
   （`Invalid query: … is not an integer`），只能并发不能合并。
6. **★ 写死颗数的断言是定时炸弹**：`_chk_gw.mjs` 的 `160/60/220`、`_audit_data.py` 的 `F1 50°壳层==160`
   在补入 2 颗星后立刻假红。改成**关系断言**（卡片颗数 == `DATA.n50`、两卡之和 == 在轨总数、
   壳层计数 == target 高度计数），数据自然增长时不再假红，真错了照样红。
   **凡是「会随发射自然变大」的数字，别写进断言。**

## 附：手机端适配 / 局域网访问（2026-10-20，用户「手机端和电脑端都能看」）

1. **★ 别靠「监听器注册先后」这种隐式约定**。想在第二根手指落下时补发 `pointercancel`
   把主脚本的 `drag` 置空，当场发没用 —— 因为主脚本的画布监听器是在
   `DOMContentLoaded` 的 `boot()` 里才注册的，**比后加载的 mobile.js 还晚**，
   于是「先取消 → 主脚本随后又把 drag 设上」，地球照样被转（实测 16.8°）。
   改成 **`queueMicrotask` 延到本轮事件处理完之后再发**，与注册顺序彻底无关。
   排查路径值得记住：`dragging` class 一直为 true + `lon` 变了固定角度
   ⇒ 先怀疑「有没有一个更晚的监听器把它设回去」。
   顺带纠正一个常见误解：**目标元素上的 capture 监听器在捕获趟先跑、普通监听器在冒泡趟后跑**，
   注册顺序只在同一趟内有效。

2. **`Array.prototype.slice.call(iterable)` 对迭代器返回空数组**。`Map.values()` 是迭代器、
   没有 `length`，slice 当成长度 0 ⇒ 后面 `p[0].x` 抛 TypeError。
   症状极具误导性：抽屉、遮罩、全屏全都正常，只有捏合无效。
   一律用 `Array.from(map.values())`。

3. **`touch-action:none` 要加在真正要吃手势的元素上**。加在 `#stage` 上会把
   `#passView` / `#batchPanel`（stage 的子元素）的滚动一起废掉 —— 祖先带 none 是**整条链**生效，
   子元素写 `auto` 也救不回来。只加 `#cv3d` / `#cv2d`。

4. **断点要按「设备横过来」的宽度选**：iPhone 14 横屏是 844×390，断点卡 820 就漏了它，
   掉回三栏后地球只剩 318×275。改成 900，另加 `(max-height:460px)` 收拾横屏矮窗。

5. **「缩短侧栏」这种小优化会连带布局**：300/320 → 252/274 让卡片换行变高，
   把卫星列表顶到页脚底下，真实鼠标点击按坐标命中就点到了 `FOOTER`（自检 7a 变红）。
   定位手法：**`document.elementFromPoint(中心点)` 打出父链**，一眼看出被谁盖住。
   结论是**回退**这个优化 —— 省 96px 换不来「点不中」的风险。

6. **局域网访问不只需要 `bind 0.0.0.0`**：`Host` 头白名单默认只认回环名，
   绑了 `0.0.0.0` 但白名单没跟着放开 ⇒ 手机 403 白屏，**电脑上一切正常**，极难联想到安全校验。
   放行「私有网段 **IP 字面量**」不削弱防 DNS 重绑定：攻击者只能用自己的域名，
   他没法让域名同时是 `192.168.1.7` 这个 Host 字符串。域名仍一律拒绝。

7. **exe 把 web/ 打进包，CSS 改了必须重打包**。本轮 `mobile.css` 在第一次打包**之后**又改了一轮
   （去掉缩窄侧栏），差点让「包里是旧 CSS」。收尾流程应是：
   改 web/ → 同步变体（`_make_nopass.py`）→ 同步 `web_live\raise\` → **重打包** → 拆包核对
   （`_verify_exe_payload.py` 已加 mobile.css / mobile.js 两项）。
